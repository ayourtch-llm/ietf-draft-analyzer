### Replay Cache State Loss Exploitation

**Severity**: critical | **Category**: StateConfusion

Demonstrates Kerberos Replay Cache State Loss Exploitation by capturing a KRB_AP_REQ, simulating server cache loss, and replaying the request.

**Setup**:
1. Step 1: Install dependencies: pip install scapy
1. Step 2: Ensure you have a Kerberos environment (KDC, client, and a vulnerable service) running.
1. Step 3: Run the script with root privileges to capture and inject packets: sudo python3 poc_replay_cache_state_loss.py

**If vulnerable**: The server accepts the replayed KRB_AP_REQ and grants access, indicating that it failed to enforce the 'reject all requests' policy after losing its replay cache state.

**If patched**: The server rejects the replayed KRB_AP_REQ, either by returning a KRB_ERROR message or by silently dropping the request, indicating that it correctly enforces the 'reject all requests' policy during the clock skew interval after cache loss.

**Caveats**:
- This PoC assumes a hypothetical mechanism to trigger cache loss on the target server.
- The script requires root privileges to capture and inject raw packets.
- The target server must be running a Kerberos service that is vulnerable to replay cache state loss.
- The script does not handle all possible Kerberos error responses or edge cases.

**Setup**:

1. Step 3: Identify a target KDC IP address and ensure network access to UDP port 88.

**If patched**: If the KDC implements rate limiting or requires pre-authentication (PA-ENC-TIMESTAMP), the attack will be mitigated. **Caveats**:

- The script assumes the target server has just restarted and lost its replay cache. Timing is critical.

### Replay Cache Race Condition in Multi-Instance Services

**Severity**: high | **Category**: RaceCondition

**Setup**:
1. Step 1: Ensure Python 3 is installed.
1. Step 2: Set up a mock multi-instance Kerberos service (e.g., using a simple HTTP server with Kerberos auth or a custom socket server) that does not share a replay cache between instances.
1. Step 3: Capture a valid KRB_AP_REQ packet from a legitimate client using a tool like Wireshark or tcpdump, and save it as 'captured_ap_req.bin'.
1. Step 4: Run the script with the path to the captured packet and the target server addresses.

**If vulnerable**: When the target service is vulnerable, multiple server instances will accept the same replayed KRB_AP_REQ. **If patched**: When the target service is patched, only the first instance to receive the replayed KRB_AP_REQ will accept it. Subsequent instances will detect the duplicate authenticator and reject it with a KRB_AP_ERR_REPEAT error. The script will report 'REJECTED' for all but one instance, indicating that the replay cache is properly synchronized.

**Caveats**:
- This script assumes that the captured KRB_AP_REQ packet is valid and has not expired.
- The script uses a simplified response analysis. In a real-world scenario, you would need to parse the KRB_ERROR message to accurately detect replay rejection.
- The script requires root privileges to send raw packets on some systems.
