### IPv6 Overlapping Fragment Firewall Bypass

**Severity**: critical | **Category**: StateConfusion

Demonstrates IPv6 Overlapping Fragment Firewall Bypass by sending overlapping fragments with modified TCP flags.

**Setup**:
1. Step 1: Ensure you have root privileges to send raw packets.
1. Step 2: Ensure the target network supports IPv6 and has a stateful firewall that inspects fragments before reassembly.
1. Step 3: Run the script with the target IPv6 address and port as arguments.

**If vulnerable**: The firewall allows the first fragment due to the SYN+ACK flags, and the second fragment overlaps to change the flags to SYN only. The destination reassembles the packet and sees a SYN-only packet, initiating a new connection.

**If patched**: The firewall or destination host detects the overlapping fragments and discards the entire datagram, preventing the connection initiation.

**Caveats**:
- Requires root privileges to send raw packets.
- The target must support IPv6 and have a stateful firewall that inspects fragments before reassembly.
- The script assumes a simple network environment without additional security measures like IPS/IDS.

### IPv6 Overlapping Fragment Firewall Bypass

**Severity**: critical | **Category**: AuthBypass

Demonstrates the IPv6 Overlapping Fragment Firewall Bypass (RFC 5722) by sending a first fragment with benign TCP flags and a second overlapping fragment that overwrites them with malicious flags.

**Setup**:
1. Step 1: Ensure you have root privileges to send raw packets.
1. Step 2: Install scapy: pip install scapy
1. Step 3: Run the script targeting a vulnerable firewall/host setup.

**If vulnerable**: The destination host receives both fragments, reassembles them, and the overlapping second fragment overwrites the TCP flags in the first fragment. The resulting packet has SYN flags, initiating a connection that the firewall allowed based on the initial SYN+ACK flags.

**If patched**: The destination host or firewall detects the overlapping fragments and silently discards the entire datagram, preventing the bypass.

**Caveats**:
- Requires raw socket privileges (root).
- Modern systems and firewalls implement RFC 8200 and discard overlapping fragments.
- The exact offset and payload size may need adjustment based on the target's MTU and firewall inspection depth.

### Eavesdropping on IPv6 Packets

**Severity**: high | **Category**: InformationLeak

Demonstrates that unencrypted IPv6 packets can be read by an on-path observer.

**Setup**:
1. Step 1: Ensure you have root privileges to create raw sockets.
1. Step 2: Run the script on a machine that can act as both sender and receiver (loopback) or on a shared network segment.
1. Step 3: The script will send a plaintext message over IPv6 and simultaneously capture it to demonstrate eavesdropping.

**If vulnerable**: The eavesdropper thread successfully captures the IPv6 packet sent by the sender thread. The payload, which contains sensitive plaintext data, is printed to the console, demonstrating that an on-path observer can read the contents of unencrypted IPv6 packets.

**If patched**: If the communication were encrypted (e.g., using TLS or IPsec), the eavesdropper would still capture the packet, but the payload would appear as ciphertext. The eavesdropper would not be able to read the sensitive information without the decryption keys.

**Caveats**:
- This script uses the loopback interface for simplicity and safety. In a real network, an attacker would need to be on the same network segment or have routing control to intercept packets.
- Raw socket operations require root privileges on most systems.
- This is not a vulnerability in the IPv6 protocol itself, but a demonstration of the need for encryption when transmitting sensitive data over untrusted networks.
- The script is for educational purposes only and should not be used to intercept traffic on networks without explicit permission.

### IPv6 Fragment Reassembly Resource Exhaustion

**Severity**: high | **Category**: DenialOfService

Proof-of-concept script demonstrating IPv6 Fragment Reassembly Resource Exhaustion by sending incomplete fragments with unique IDs.

**Setup**:
1. Step 1: Ensure the script is run with root privileges (required for raw sockets).
1. Step 2: Identify the target IPv6 address and a valid source IPv6 address on the same network segment.
1. Step 3: Run the script with the target address as an argument: python3 poc_ipv6_fragment_reassembly_exhaustion.py <TARGET_IPv6>

**If vulnerable**: The target node allocates a reassembly buffer for each unique Fragment Identification value. Since the script never sends the final fragment (M=0) or subsequent fragments, the target holds these buffers for the maximum reassembly timeout (typically 60 seconds per RFC 8200). High volume leads to memory exhaustion and increased CPU usage for timer management, resulting in a Denial of Service.

**If patched**: The target node implements strict limits on the number of concurrent reassembly contexts per source IP or globally. It may also use randomized timeouts or rate-limit fragment reception. As a result, the target discards excess fragments early, preventing resource exhaustion.

**Caveats**:
- Requires root privileges to create raw sockets.
- The target must support IPv6 and implement fragment reassembly.
- Some modern OSes have built-in protections against this specific attack (e.g., limits on reassembly contexts).
- The ICMPv6 checksum in the payload is simplified for demonstration; some strict implementations may drop packets with invalid checksums before reassembly.
- Network interfaces or firewalls may drop fragmented packets by default.

### IPv6 Overlapping Fragment Reassembly Race

**Severity**: high | **Category**: RaceCondition

Demonstrates the IPv6 Overlapping Fragment Reassembly Race (RFC 5722) by sending a benign first fragment followed by a malicious overlapping second fragment to bypass firewall inspection.

**Setup**:
1. Step 1: Install Scapy: pip install scapy
1. Step 2: Run with root privileges: sudo python3 poc_ipv6_overlapping_fragment_race.py
1. Step 3: Ensure the target IPv6 address is reachable and a firewall/IDS is inspecting fragments before reassembly.

**If vulnerable**: The firewall inspects the first fragment, sees a SYN-ACK, and allows it through as a legitimate response. The second overlapping fragment arrives and overwrites the TCP header with a SYN flag. The destination host reassembles the packet and sees a SYN request, initiating a connection that bypassed the firewall's stateful inspection rules.

**If patched**: The destination host or an inline firewall detects that the second fragment overlaps with the first fragment's region. Per RFC 5722 and RFC 8200, the entire datagram is discarded immediately, and no connection is established. An ICMP error may or may not be generated depending on implementation.

**Caveats**:
- Requires raw socket privileges (root/admin).
- IPv6 must be enabled and reachable on the target network.
- The race condition depends on the specific implementation of the firewall/IDS and the OS reassembly buffer.
- Modern firewalls often perform full reassembly before inspection, mitigating this specific attack vector.

### IPv6 Fragment Offset Manipulation for Oversized Reassembly

**Severity**: high | **Category**: OversizedPayload

Demonstrates IPv6 Fragment Offset Manipulation to trigger oversized reassembly buffer overflows or DoS.

**Setup**:
1. Step 1: Ensure you have root privileges to send raw IPv6 packets.
1. Step 2: Identify the target IPv6 address and ensure network connectivity.
1. Step 3: Run the script with the target IPv6 address as an argument.

**If vulnerable**: The target node fails to validate the reassembled packet size against the 65,535 octet limit. It may allocate a buffer based on the first fragment's size or fail to check bounds, leading to a heap overflow, memory corruption, or denial of service (crash/hang) when processing the oversized reassembled packet.

**If patched**: The target node correctly implements RFC 8200 Section 4.5. Upon receiving the second fragment, it calculates the potential reassembled size (Offset * 8 + Payload Length). Since this exceeds 65,535 octets, it discards the fragment and sends an ICMPv6 Parameter Problem (Code 0) message back to the source, pointing to the Fragment Offset field.

**Caveats**:
- Requires root privileges to send raw IPv6 packets.
- Firewalls or intermediate devices may drop fragmented packets or ICMP error messages.
- The source IP must be routable or valid for the target to send ICMP errors back.
- Some operating systems may have different default behaviors for fragment reassembly timeouts or buffer sizes.

### IPv6 Atomic Fragment State Confusion

**Severity**: high | **Category**: StateConfusion

Demonstrates IPv6 Atomic Fragment State Confusion by sending a fragmented packet with Offset=0 and M=0 to test reassembly handling.

**Setup**:
1. Step 1: Ensure the host has IPv6 connectivity and a raw socket capability (run as root or with CAP_NET_RAW).
1. Step 2: Identify a target IPv6 address that supports ICMPv6 Echo Reply (e.g., a local router or host).
1. Step 3: Run the script with the target IPv6 address as an argument.

**If vulnerable**: The target host enters a reassembly wait state for the atomic fragment, consuming memory resources. No ICMP Echo Reply is sent because the host is waiting for more fragments that will never arrive. If many such packets are sent, it can lead to denial of service by exhausting reassembly buffers.

**If patched**: The target host correctly identifies the atomic fragment (Offset=0, M=0) as a complete packet. It processes it immediately, strips the Fragment header, and sends an ICMP Echo Reply. No reassembly state is created.

**Caveats**:
- Requires root privileges or CAP_NET_RAW to send raw IPv6 packets.
- Firewalls may drop fragmented packets by default, which could mask the vulnerability.
- The script assumes the target supports ICMPv6 Echo Reply. If ICMP is blocked, the lack of response is ambiguous.
- Some systems may have aggressive fragment dropping policies that mitigate this issue without fixing the underlying state confusion.

### Fragment Reassembly Ambiguity in Overlap Handling

**Severity**: high | **Category**: ImplementationAmbiguity

Demonstrates IPv6 fragment reassembly ambiguity by injecting exact duplicate fragments to test inconsistent handling between firewalls and end-hosts.

**Setup**:
1. Step 1: Ensure you have root privileges to send raw packets.
1. Step 2: Configure a target IPv6 address (e.g., a local interface or a test server).
1. Step 3: Run the script with the target IPv6 address as an argument: python3 poc_fragment_reassembly_ambiguity.py <TARGET_IPV6>

**If vulnerable**: The end-host successfully reassembles the packet and processes the UDP payload, while a strict firewall in the path may drop the entire datagram due to the overlapping fragment. This leads to a state desynchronization where the firewall believes the packet was dropped, but the end-host processes it, potentially bypassing security controls or causing inconsistent logging.

**If patched**: Both the firewall and the end-host treat the duplicate fragment as an overlapping fragment and silently discard the entire datagram, resulting in no packet processing at the end-host and consistent behavior across network devices.

**Caveats**:
- This PoC requires root privileges to send raw IPv6 packets.
- The target must support IPv6 and have a service listening on the destination port (UDP 8080 in this example).
- Firewall behavior may vary significantly depending on the vendor and configuration.
- The script assumes a local or directly reachable IPv6 target. Adjust src_ipv6 and target_ipv6 as needed for your environment.
- Some operating systems may have built-in protections against fragment attacks that could interfere with the test.
