### Open Relay via Missing Relay Policy Validation

**Severity**: critical | **Category**: MissingValidation

Demonstrates SMTP Open Relay vulnerability by attempting to relay mail to an external domain without authentication.

**Setup**:
1. Step 1: Ensure Python 3 is installed.
1. Step 2: Identify a target SMTP server suspected of being an open relay (e.g., on port 25).
1. Step 3: Run the script with the target server's IP address and port.

**If vulnerable**: The server accepts the RCPT TO command for an external domain with a 250 OK response, allowing the attacker to send the DATA command and complete the email transaction. This indicates the server is an open relay.

**If patched**: The server rejects the RCPT TO command for an external domain with a 550 error (e.g., '550 5.7.1 Relaying denied'), indicating that relay policy validation is properly enforced.

**Caveats**:
- This script is for educational and authorized testing purposes only.
- Ensure you have explicit permission to test the target SMTP server.

- The script uses a dummy external domain; do not use real domains to avoid spam complaints.

### EHLO to HELO Downgrade

**Severity**: high | **Category**: Downgrade

Demonstrates the EHLO-to-HELO downgrade attack in SMTP by simulating an on-path attacker that drops EHLO commands, forcing the client to fall back to the legacy HELO command and bypass security extensions.

**Setup**:
1. Step 1: Ensure Python 3 is installed.
1. Step 2: Run the script. It will start a mock SMTP server and a mock SMTP client on localhost.
1. Step 3: The script simulates an on-path attacker by intercepting the client's EHLO command and dropping it, triggering the client's fallback to HELO.

**If vulnerable**: The client sends EHLO, but the attacker drops it. The client times out and falls back to HELO. The server responds to HELO without advertising STARTTLS or other extensions, effectively bypassing security features.

**If patched**: If the server is configured to reject HELO commands or enforce TLS (e.g., SMTP TLS Mandatory), it will either reject the HELO command or refuse to proceed with mail transactions, preventing the downgrade.

**Caveats**:
- This is a simulation using local sockets. In a real attack, the attacker would need to be on-path between the client and server.
- The client's fallback behavior depends on its implementation of RFC 5321 Section 3.2.
- Modern clients may have stricter fallback policies or enforce TLS, mitigating this attack.

**Setup**:
1. Step 1: Ensure Python 3 is installed.

1. Step 3: Run the script with the target IP/hostname and optional port (default 25).

A '252' response indicates that the server cannot verify the address or expand the list without revealing information, effectively neutralizing the enumeration attempt.

**Caveats**:
- This script is for educational and authorized testing purposes only.
- Some SMTP servers may rate-limit or block connections after repeated VRFY/EXPN attempts.
- The script uses a hardcoded list of test users and mailing lists; real-world attacks would use larger wordlists.
- Modern SMTP servers often disable VRFY/EXPN by default due to well-known security risks.
- Network firewalls or IDS/IPS systems may detect and block these commands.

**Setup**:
1. Step 1: Ensure Python 3 is installed.
1. Step 2: Identify a target SMTP server that generates bounce messages and lacks robust loop detection or null reverse-path enforcement.
1. Step 3: Run the script with the target server's address and port.

**If patched**: The SMTP server either rejects the message with a forged return path, enforces a null reverse-path (MAIL FROM:<>) for bounce messages, or detects and stops the loop by counting 'Received:' headers, preventing the bounce storm.

- This script is for educational and testing purposes only.
- Ensure you have explicit permission to test the target SMTP server.
- The behavior may vary depending on the server's configuration and loop detection mechanisms.
