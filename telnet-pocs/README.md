### LINEMODE Mode Negotiation Replay

**Severity**: critical | **Category**: ReplayAttack

Demonstrates replaying a captured LINEMODE MODE suboption to force a vulnerable Telnet client into Remote Line Editing mode.

**Setup**:
1. Step 1: Ensure Python 3 is installed.
1. Step 2: Identify a target Telnet server that supports LINEMODE (RFC 1184).
1. Step 3: Run the script in a man-in-the-middle position or against a vulnerable local test client.

**If vulnerable**: The vulnerable client processes the replayed LINEMODE MODE command without checking if it's out of sequence. The client switches to Remote Line Editing mode (or another specified mode), causing all subsequent input to be sent raw to the server, bypassing local signal handling and potentially exposing sensitive data like passwords.

**If patched**: The patched client implements strict state machine validation for Telnet option negotiation. It rejects LINEMODE MODE commands that are not part of an active negotiation phase or that duplicate previous states without explicit re-negotiation triggers. The replayed packet is ignored, and the client remains in its current mode.

**Caveats**:
- This PoC assumes the attacker has network-level access (on-path) to intercept and inject packets.
- Real-world exploitation requires capturing a valid LINEMODE MODE command from an active session first.
- Modern Telnet clients often default to simpler modes or use SSH, reducing exposure.
- The script demonstrates packet construction; actual impact depends on the specific client implementation's handling of out-of-sequence options.

### Ambiguous Option Coupling and State Inference

**Severity**: high | **Category**: ImplementationAmbiguity

Demonstrates how legacy Telnet implementations infer local line editing mode from ECHO/SGA option states instead of explicit LINEMODE negotiation.

**Setup**:
1. Step 1: Ensure Python 3 is installed with standard libraries (socket, struct).
1. Step 2: Identify a target Telnet server that may use legacy behavior (e.g., an old BSD-based telnetd or custom implementation).
1. Step 3: Run the script against the target's IP and port (default 23).

**If vulnerable**: The target server incorrectly processes input as if local line editing mode is active, even though only ECHO and SGA options were negotiated. This manifests as unexpected buffering behavior, incorrect echo responses, or processing of special characters that should be handled by explicit LINEMODE negotiation.

**If patched**: The target server strictly follows RFC 1184 LINEMODE state machine for line editing features. When only ECHO and SGA are negotiated without LINEMODE, the server maintains standard character-at-a-time mode without inferring local line editing capabilities.

**Caveats**:
- Requires a live Telnet server target that may use legacy implementation behavior
- Results may vary depending on specific Telnet daemon configuration and version
- Some modern servers explicitly disable option coupling, making this PoC less effective
- Network latency can affect timing-sensitive observations of buffering behavior

### SLC Special Character Replay

**Severity**: high | **Category**: ReplayAttack

Demonstrates how an attacker can replay a captured LINEMODE SLC configuration command to override terminal special character mappings, potentially causing DoS or unexpected behavior.

**Setup**:
1. 1. Install Python 3 and the `scapy` library (pip install scapy).
1. 2. Identify a target Telnet server that supports LINEMODE (e.g., on port 23) or simulate a vulnerable client environment.
1. 3. Ensure you have network access to send raw packets to the target.

**If vulnerable**: If the target Telnet client or server is vulnerable to SLC replay attacks, it will process the malicious SLC command. The terminal may exhibit unexpected behavior: typing 'Backspace' might trigger an IAC IP (Interrupt Process) signal instead of erasing a character, or the connection might drop due to protocol confusion caused by the overridden special characters.

**If patched**: If the target is patched, it will either ignore the SLC command because it was not part of a valid negotiation sequence, reject out-of-order updates, or validate that the new settings do not conflict with current session state. The terminal behavior remains normal, and no disruption occurs.

**Caveats**:
- This PoC assumes the LINEMODE option is already negotiated or can be forced. In a real attack, the attacker might need to inject LINEMODE negotiation first.
- The script sends raw TCP packets; ensure you have authorization to test the target system.
- Modern Telnet implementations may disable LINEMODE by default or validate SLC commands more strictly.

### Ambiguous Default Mode Transition upon LINEMODE Negotiation

**Severity**: high | **Category**: ImplementationAmbiguity

Demonstrates ambiguous handling of SLC defaults and FORWARDMASK state when LINEMODE MODE 0 is negotiated.

**Setup**:
1. Step 1: Identify a target telnet server that supports LINEMODE (e.g., an older UNIX system or a specific Telnet daemon).
1. Step 2: Ensure you have network access to the target on port 23 (or specified port).
1. Step 3: Run the script as a client initiating LINEMODE negotiation.

**If vulnerable**: The server incorrectly interprets special characters (like Ctrl+C) as interrupt signals despite MODE 0 and SLC_NOSUPPORT defaults, or fails to send the correct WONT/DONT FORWARDMASK subnegotiation, leading to inconsistent terminal behavior.

**If patched**: The server correctly ignores special characters (SLCs) when in MODE 0 with SLC_NOSUPPORT defaults and properly initializes the FORWARDMASK state to WONT/DONT, maintaining stable connection behavior.

**Caveats**:
- Requires a target Telnet server that supports LINEMODE option negotiation.
- The exact byte sequences for subnegotiation commands may vary slightly depending on implementation-specific extensions.
- Testing should be performed in a controlled environment to avoid unintended service disruption.

### Telnet LINEMODE State Confusion / Local Line Editing Bypass

**Severity**: high | **Category**: AuthBypass

Demonstrates Telnet LINEMODE negotiation forcing local line editing mode to bypass character-at-a-time input processing in legacy auth daemons.

**Setup**:
1. Step 1: Ensure Python 3 is installed with standard libraries (socket, struct).
1. Step 2: Start a vulnerable Telnet server or use a known legacy implementation that supports LINEMODE and relies on character-at-a-time echoing for authentication prompts.
1. Step 3: Identify the target IP and port (default Telnet is 23).

**If vulnerable**: The server enters Local Line Editing mode and buffers the entire credential payload until CR LF is received. If the authentication daemon relies on character-at-a-time processing (e.g., for password prompts), it may fail to validate credentials properly or be bypassed entirely, resulting in an 'Access granted' message.

**If patched**: The server either rejects the LINEMODE negotiation, ignores the Local Line Editing mode request, or processes input character-by-character regardless of the LINEMODE state. The authentication daemon correctly validates credentials, and access is denied.

**Caveats**:
- This PoC targets legacy Telnet implementations that support LINEMODE (RFC 1184) and rely on character-at-a-time echoing for authentication.
- Modern Telnet servers typically disable LINEMODE by default or enforce strict state machine transitions, mitigating this vulnerability.
- The success of the bypass depends on the specific implementation of the server's authentication daemon and its handling of buffered input.

### Telnet LINEMODE Downgrade via Forced Mode Mask

**Severity**: high | **Category**: Downgrade

Demonstrates on-path manipulation of Telnet LINEMODE negotiation to disable EDIT and TRAPSIG security bits.

**Setup**:
1. Step 1: Install required libraries (scapy is recommended for packet crafting, or use raw sockets).
1. Step 2: Identify the target IP and port (default Telnet is 23).
1. Step 3: Ensure you have network access to inject packets between client and server (e.g., via ARP spoofing or a controlled lab environment).

**If vulnerable**: The client accepts the attacker-injected LINEMODE MODE command with EDIT and TRAPSIG bits unset. The connection enters RAW_MODE, meaning local editing and signal trapping are disabled. All input is sent in cleartext to the server.

**If patched**: The client or server rejects the LINEMODE MODE command that attempts to clear EDIT or TRAPSIG bits after they have been initially set or negotiated as secure. The connection remains in a mode with local editing and signal trapping enabled.

**Caveats**:
- This PoC simulates the injection of packets. In a real-world scenario, an attacker would need to be on-path (e.g., via ARP spoofing) to intercept and modify these packets.
- The script assumes the target Telnet server supports LINEMODE and responds to negotiation commands.
- Modern Telnet implementations may have mitigations in place that prevent this downgrade.

### MissingValidationOfSLCValues

**Severity**: high | **Category**: MissingValidation

Demonstrates missing validation of LINEMODE SLC parameters by sending malformed character codes and levels to a Telnet server.

**Setup**:
1. Step 1: Ensure Python 3 is installed.
1. Step 2: Start a vulnerable Telnet server that supports the LINEMODE option (e.g., `telnetd` or a custom test server).
1. Step 3: Identify the IP and port of the target Telnet service.

**If vulnerable**: The target Telnet server processes the malformed SLC parameters without strict validation. It may respond with unexpected negotiation commands (DO/DONT), enter an unrecoverable state, crash, or exhibit undefined line editing behavior due to invalid character codes or level bits being applied.

**If patched**: The target Telnet server strictly validates all SLC parameters against RFC-defined ranges and local capabilities. It rejects malformed subnegotiations by sending a NOSUPPORT response (or ignoring them) without altering its internal state, maintaining stable operation.

**Caveats**:
- Telnet LINEMODE negotiation is complex; the PoC assumes basic LINEMODE support is available.
- Some Telnet servers may not enable LINEMODE by default or require specific configuration.
- The exact byte sequences for SLC commands can vary slightly between implementations; RFC 1184 should be consulted for precise definitions.
- This PoC demonstrates protocol-level validation flaws; actual exploitation (e.g., DoS) depends on the server's internal handling of invalid values.

### TOCTOU in LINEMODE MODE Negotiation

**Severity**: high | **Category**: RaceCondition

Demonstrates TOCTOU race condition in LINEMODE MODE negotiation by injecting conflicting MODE masks.

**Setup**:
1. 1. Identify a target Telnet server that supports LINEMODE (RFC 1184).
1. 2. Ensure you are on-path or have direct access to the target port (usually 23).
1. 3. Run the script with `python3 poc_linemode_toctou.py <target_ip> [target_port]`.

**If vulnerable**: The client responds with a LINEMODE MODE subnegotiation that reflects an inconsistent or unintended mode mask (e.g., BATCH enabled but EDIT disabled unexpectedly), or the connection enters RAW_MODE due to unserialized state transitions.

**If patched**: The client ignores out-of-order or duplicate MODE commands, or strictly serializes them using sequence numbers. The final mode mask matches the last valid command received in order, and no inconsistent state is observed.

**Caveats**:
- Requires on-path access to inject packets.
- Target must support LINEMODE (RFC 1184).
- Modern Telnet clients may have mitigated this by implementing strict sequence tracking.
- Parsing of raw Telnet subnegotiations in the PoC is simplified; real-world exploitation may require more robust packet analysis.

### LINEMODE Mode Mask Race Condition

**Severity**: high | **Category**: StateConfusion

Demonstrates the LINEMODE Mode Mask Race Condition by sending rapid, conflicting MODE commands to induce state desynchronization between client and server.

**Setup**:
1. Step 1: Ensure Python 3 is installed.
1. Step 2: Identify a target Telnet server that supports LINEMODE (RFC 1184). Note the IP address and port (default 23).
1. Step 3: Install required libraries if not present: `pip install scapy` (optional, but standard socket is sufficient for this raw implementation).

**If vulnerable**: The server enters a state of confusion where it may stop responding to further commands, drop the connection, or operate in an incorrect mode (e.g., expecting raw input but receiving edited characters). The race condition causes the internal mode mask to become inconsistent with the actual negotiation state.

**If patched**: The server correctly handles concurrent MODE commands by enforcing strict turn-taking or using sequence numbers. It acknowledges the first valid command and ignores or queues subsequent conflicting commands until the state is synchronized, maintaining a consistent mode throughout the session.

**Caveats**:
- This PoC requires a target that actively supports LINEMODE (RFC 1184). Many modern Telnet servers default to TELOPT or have LINEMODE disabled.
- The race condition window is narrow and may require precise timing adjustments depending on network latency.
- Some implementations may simply reject invalid subnegotiation sequences, preventing the exploit from causing state confusion but potentially leading to a DoS via connection reset.
